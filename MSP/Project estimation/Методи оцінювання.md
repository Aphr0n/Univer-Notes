
# 1. Work Breakdown Structure (WBS)
Проєкт розбивається на найдрібніші задачі, кожна оцінюється окремо, потім усе сумується. Чотири кроки: розбити, розподілити між людьми, оцінити зусилля, перевірити.

Коли: коли обсяг відомий і його можна декомпозувати. Це основа bottom-up підходу.

# 2. 3-Point Estimation

Для задачі даються три значення: a (найкращий випадок), m (найімовірніший), b (найгірший). Підсумкова оцінка зазвичай рахується за PERT: E = (a + 4m + b) / 6.

Приклад: a = 4 дні, m = 6, b = 14. E = (4 + 24 + 14) / 6 = 7 днів. Бачиш, що оцінка вища за «найімовірніше» через ризик гіршого сценарію.

Коли: коли є велика невизначеність у конкретній задачі.

# 3. Wideband Delphi

Група експертів оцінює незалежно, потім обговорює розбіжності й повторює кілька раундів до збіжності. Мета: отримати неупереджену оцінку без впливу найгучнішого учасника.

Коли: коли потрібна висока впевненість і є кілька знаючих людей.

# 4. Function Point Analysis (FPA)

Розмір системи вимірюється в «function points» за кількістю та складністю вхідних даних, виходів, запитів, внутрішніх і зовнішніх файлів. Потім розмір переводиться в зусилля через історичну продуктивність. Це по суті параметричний метод.

Коли: коли відомі функціональні вимоги, але ще немає коду.

# 5. Use-Case Point Method

Схожий на FPA, але розмір рахується за use case-ами та акторами (з урахуванням складності), плюс коригувальні фактори середовища й технічної складності. Звідси й UUCP, UFP/VAF у твоїх завданнях (UFP/VAF належить до FPA, UUCP до UCP).

Коли: коли вимоги описані як use case-и.

# 6. Percentage distribution

Загальне зусилля розподіляється за фазами у відсотках на основі історичних даних (наприклад, аналіз 10%, проєктування 20%, кодування 40%, тестування 30%). Якщо знаєш оцінку однієї фази, можеш вивести решту.

Коли: для швидкої перевірки або планування розподілу ресурсів по фазах.

# 7. Ad-hoc method

Оцінка «з голови», без формального методу, на основі інтуїції та досвіду. Швидко, але найменш надійно й важко обґрунтувати.

Коли: лише для грубої прикидки на ранньому етапі, але не як єдина оцінка.


>[!warning] Слід використовувати щонайменше два методи й порівнюй результати. Збіжність означає, що оцінка хороша, великий розкид означає, що треба розбиратися.
