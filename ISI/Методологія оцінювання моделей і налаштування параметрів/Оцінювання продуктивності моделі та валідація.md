# Underfitting — недонавчання (High Bias)
Недонавчання виникає тоді, коли модель занадто проста, щоб знайти закономірності в даних.

**Ознаки:**
- Низька точність на тренувальних даних.
- Низька точність на тестових даних.
- Модель погано знаходить закономірності.

**Як виправити:**
- Використати складнішу модель.
- Додати нові корисні ознаки.
- Зменшити надмірне обмеження моделі.

# Overfitting — перенавчання (High Variance)
Перенавчання виникає тоді, коли модель занадто сильно пристосовується до тренувальних даних. Вона запам'ятовує не тільки закономірності, а й шум та випадкові особливості.

**Ознаки:**
- Дуже висока точність на тренувальних даних.
- Значно нижча точність на тестових.
- Велика різниця між train та validation результатами.

**Як виправити:**
- Зменшити складність моделі.
- Додати більше навчальних даних.
- Видалити зайві або шумові ознаки.
- Використати регуляризацію.
- Застосувати Cross-validation.

# Good fit — хороший компроміс
Це ситуація, коли модель:
- достатньо складна, щоб знаходити закономірності;
- не настільки складна, щоб запам'ятовувати шум;
- добре працює як на тренувальних, так і на нових даних.

## Bias-Variance Trade-off
Це компроміс між відхиленням (Bias) та розкидом (Variance):
- **Bias (відхилення)** — помилка, яка виникає через надмірно прості припущення моделі.
- **Variance (розкид)** — чутливість моделі до змін у тренувальних даних.

| Ситуація         | Bias     | Variance |
| :--------------- | :------- | :------- |
| **Underfitting** | Високий  | Низький  |
| **Good fit**     | Помірний | Помірний |
| **Overfitting**  | Низький  | Високий  |

# 3.4. Hold-out method
Це метод розділення даних на дві частини:
- **Training set** — для навчання.
- **Test set** — для перевірки.

Наприклад, маємо 1000 записів:
- 800 — тренувальні;
- 200 — тестові.


## 3.5. Train / Validation / Test
Щоб уникнути цієї проблеми, додаємо третій набір — **Validation**. Тепер є три частини:

1. **Training set** — використовується для навчання моделі.
2. **Validation set** — використовується для:
   - вибору моделі;
   - налаштування гіперпараметрів;
   - порівняння різних конфігурацій.
3. **Test set** — використовується для остаточної незалежної оцінки якості моделі.

**Наприклад:**

| Набір | Кількість |
| :--- | :--- |
| Training | 700 |
| Validation | 150 |
| Test | 150 |
| **Разом** | **1000** |

**Послідовність роботи:**
1. Навчаємо модель на Training.
2. Перевіряємо на Validation.
3. Змінюємо параметри, якщо потрібно.
4. Після вибору конфігурації перевіряємо її на Test.

> **Важливо:** Тестовий набір не використовують для підбору гіперпараметрів. Інакше остаточна оцінка вже не буде незалежною.

**Недолік цього підходу:** результат залежить від того, як саме ми розділили дані. Саме цю проблему розв'язує наступна тема.
