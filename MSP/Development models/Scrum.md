Scrum — це підхід до організації розробки, у якому робота поділяється на короткі цикли — спринти (Sprints). Після кожного спринту команда отримує певну частину готового продукту.

![[Pasted image 20261120211445.png]]

- Product Backlog — загальний список завдань і функцій, які потрібно реалізувати.
- Sprint Backlog — завдання, відібрані для поточного спринту.
- Daily Scrum Meeting — щоденна зустріч команди.Традиційно учасники обговорюють:
	- Що зроблено?
	- Що планується зробити?
	- Які є перешкоди?
- 2–4 Weeks — тривалість спринту, зазначена на слайді.
- 24 Hours — періодичність Daily Scrum.
- Potentially Shippable Product Increment — потенційно готовий до постачання інкремент продукту, отриманий після спринту.
- Sprint - команда розробляє, тестує та перевіряє вибрані функції. Щодня проводить Daily Scrum.
# Scrum model
![[Pasted image 20261120212328.png]]

- Plan — планування.
- Build — створення функціональності.
- Test — тестування.
- Review — перевірка результату.
Ці чотири дії повторюються кілька разів. Після них на схемі показані загальні етапи:
- Review — підсумкова перевірка результату.
- Deploy — розгортання продукту.

| Переваги                                     | Недоліки                                                         |
| -------------------------------------------- | ---------------------------------------------------------------- |
| Регулярно отримуємо результати розробки.     | Потрібна постійна комунікація команди.                           |
| Можна враховувати відгуки замовника.         | Необхідна активна участь замовника або представника бізнесу.     |
| Проблеми виявляються раніше.                 | Без належної організації зустрічі можуть забирати забагато часу. |
| Команда може адаптувати плани між спринтами. | Часті зміни пріоритетів можуть ускладнювати планування.          |
