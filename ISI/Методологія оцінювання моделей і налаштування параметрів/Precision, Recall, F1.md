# Precision — точність позитивних передбачень
Показує, скільки серед усіх об'єктів, які модель назвала позитивними, дійсно є позитивними (*«Якщо модель сказала, що об'єкт позитивний, наскільки ймовірно, що вона має рацію?»*):

$$Precision = \frac{TP}{TP + FP}$$

У нашому прикладі:
$$Precision = \frac{40}{40 + 5} \approx 88.89\%$$

- **Коли важливий?** Наприклад, у системі блокування банківських транзакцій, де помилкове блокування створює проблеми для користувачів.

# Recall — повнота
Показує, яку частину всіх справжніх позитивних об'єктів модель змогла знайти (*«Скільки всіх позитивних випадків ми змогли знайти?»*):

$$Recall = \frac{TP}{TP + FN}$$

У нашому прикладі:
$$Recall = \frac{40}{40 + 10} = 80\%$$

- **Коли важливий?** Під час діагностики небезпечного захворювання, де набагато гірше пропустити хворого, ніж помилково відправити здорового на додаткове обстеження.

## Precision проти Recall

| Precision                                   | Recall                                                 |
| :------------------------------------------ | :----------------------------------------------------- |
| Наскільки правильні позитивні передбачення? | Скільки позитивних об'єктів знайшли?                   |
| Враховує `FP`                               | Враховує `FN`                                          |
| Важливий, коли дорогі хибні тривоги         | Важливий, коли небезпечно пропускати позитивні випадки |

# F1
**F1-score** — це гармонійне середнє Precision і Recall, яке об'єднує обидві метрики:

$$F1 = 2 \cdot \frac{Precision \cdot Recall}{Precision + Recall}$$

- $F1$ близько $1$ — хороший баланс Precision і Recall.
- $F1$ близько $0$ — поганий результат.

> [!warning] Високий F1 не означає автоматично, що модель ідеальна, і не замінює аналіз інших метрик.
