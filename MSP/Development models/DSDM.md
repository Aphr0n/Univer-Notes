DSDM — це методологія розробки програмного забезпечення, яка використовує ітерації та прототипування. Aкцент зроблено на трьох великих циклах роботи: Functional Model Iteration, Design & Build Iteration та Implementation.

У DSDM є два окремі цикли прототипування:

| Цикл                       | Основний фокус            |
| -------------------------- | ------------------------- |
| Functional Model Iteration | Функціональність системи  |
| Design & Build Iteration   | Дизайн і побудова системи |

*Feasibility* — оцінка здійсненності проєкту: чи реально його реалізувати.
*Business Study* — дослідження бізнес-потреб: яку проблему має розв'язати система та що потрібно організації.

## Functional Model Iteration
Тут команда створює прототип функцій системи та перевіряє, чи відповідають вони потребам користувачів.
1. *Agree Schedule* — узгодити графік.
2. *Identify Functional Prototype* — визначити функціональний прототип, який потрібно створити.
3. *Create Functional Prototype* — створити прототип функціональності.
4. *Review Prototype* — перевірити прототип.

## ## **Design & Build Iteration**

Цей цикл зосереджений на дизайні та побудові системи.

Він також має чотири кроки:
- *Agree Schedule* — узгодити графік.
- *Identify Design Prototype* — визначити прототип дизайну.
- *Create Design Prototype* — створити прототип дизайну.
- *Review Design Prototype* — перевірити прототип дизайну.

## Implementation
- **Implement** — впровадити систему.
- **Train Users** — навчити користувачів.
- **User Approval & User Guidelines** — отримати схвалення користувача та підготувати інструкції.
- **Review Business** — переглянути бізнес-результат.
