RAD (Rapid Application Development) — модель швидкої розробки програмного забезпечення. Головна особливість — тісна взаємодія між проєктуванням і створенням продукту, з можливістю багаторазового повернення та вдосконалення.

# Етапи
## Requirements Planning — планування вимог
На цьому етапі визначають:
- що має робити система;
- які основні потреби користувачів;
- які цілі та межі проєкту.

## User Design — проєктування за участю користувача
Створюють і уточнюють дизайн системи, взаємодію з користувачем та її функції.

>[!warning] Kористувач бере активну участь у цьому процесі й може давати зворотний зв'язок.

## Construction — створення

Розробники реалізують систему. Але, як видно зі схеми, цей етап має двосторонній зв'язок із User Design.

Тобто проєктування та реалізація можуть повторюватися:

- створили частину функціональності;
- показали користувачу;
- отримали відгук;
- змінили дизайн або вимоги;
- продовжили розробку.

## Cutover — перехід до використання

Фінальний етап — підготовка системи до реального використання та її впровадження.

# Переваги й недоліки
| Переваги                                      | Недоліки                                                                     |
| --------------------------------------------- | ---------------------------------------------------------------------------- |
| Швидке отримання робочих частин продукту.     | Потрібна активна участь користувачів.                                        |
| Активна участь користувача.                   | Часті зміни можуть ускладнювати координацію.                                 |
| Можливість швидко враховувати зміни.          | Підхід може бути складним для великих систем із багатьма залежностями.       |
| Регулярне уточнення дизайну під час розробки. | Швидкість розробки залежить від доступності досвідченої команди та ресурсів. |
