# FDD — Feature-Driven Development
Розробка, орієнтована на функції (features) системи. Робота організовується навколо окремих функцій, які потрібно реалізувати.
Замість того щоб розробляти всю систему одним великим блоком, можна зосереджуватися на конкретних функціях.

# TDD — Test-Driven Development
Розробка, керована тестами.
Основна ідея: спочатку створюють тест, який перевіряє потрібну поведінку, а потім пишуть код, щоб цей тест пройшов.
## Типовий цикл
- Написати тест, який поки не проходить
- Написати мінімальний код, щоб тест пройшов
- Покращити код, не порушивши роботу тестів

# XP — Extreme Programming
XP — підхід, який наголошує на практиках якісної розробки та тісній співпраці команди.

Серед відомих практик XP:
- Pair Programming — програмування в парі;
- Continuous Integration — постійна інтеграція змін;
- часті релізи;
- постійний зворотний зв'язок;
- простий дизайн.

# BDD — Behavior-Driven Development
Розробка, керована поведінкою.
Тут увага приділяється тому, як система повинна поводитися з погляду користувача або бізнесу.
Наприклад:
- Given — користувач додав товар у касу.
- When — натиснув кнопку оплати.
- Then — система повинна перейти до процесу оплати.

# DDD — Domain-Driven Design
Проєктування, орієнтоване на предметну область.
Domain — це сфера, для якої створюється програмне забезпечення.
Наприклад, для каси самообслуговування предметна область — роздрібна торгівля та процес продажу товарів.
Розробники мають добре розуміти поняття цієї сфери:
- товар;
- ціна;
- знижка;
- замовлення;
- оплата;
- повернення.
Важливо правильно відобразити бізнес-логіку цієї сфери в архітектурі та коді.
